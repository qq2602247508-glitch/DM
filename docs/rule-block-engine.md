# D&D 5e 2024 规则积木引擎

## 目标

规则内容与执行代码分离。职业、法术、武器、怪物动作、物品、状态、
地形、休息和奖励先编译为同一种有版本的规则计划，再由通用解释器执行。
规则正文是来源与说明，不直接作为可写状态的运行代码。

## 通用执行链

每次规则操作都遵循：

1. 触发与前置条件；
2. 选择施法者、目标、地点或范围模板；
3. 检查并预留动作、法术位、充能、物品或职业资源；
4. 执行攻击、检定、豁免或无骰判定；
5. 计算共享或逐目标的伤害、治疗、移动和状态；
6. 创建持续、专注、重复豁免、召唤或反应触发；
7. 生成确定性的差异预览；
8. DM 或合法玩家确认后原子写入；
9. 写入战斗/推进日志并支持幂等重放。

## 积木类型

- `trigger`：动作时机、反应条件、回合阶段、进入区域、互动或任务事件。
- `target`：自己、单体、多体、物体、地点和选择上限。
- `range`：触碰、距离、圆形、锥形、直线、立方体与自定义模板。
- `roll`：攻击、技能检定、先攻和对抗检定。
- `save`：豁免属性、DC、成功/失败分支和重复时机。
- `damage` / `heal`：骰式、类型、共享骰、逐目标修正、临时 HP。
- `condition`：添加、移除、免疫、结束条件和持续时间。
- `move`：自愿移动、强制移动、传送、倒地与路径限制。
- `resource`：动作经济、法术位、弹药、充能、物品和职业资源。
- `duration`：轮数、分钟、休息、专注、永久及提前结束条件。
- `repeat` / `choice`：多次攻击、射线、飞弹分配、任选分支。
- `summon`：召唤、伙伴、变形模板和控制权。
- `reward`：经验、金币、物品、任务进度和一次性发放锁。
- `manual`：规则库尚不能可靠结构化的部分，明确停在 DM 确认。

## 同样积木化的产品域

| 产品域 | 复用积木 |
|---|---|
| 法术、武器、怪物动作 | target/range/roll/save/damage/resource |
| 职业与子职成长 | prerequisite/choice/resource/grant |
| 状态、专注与死亡 | trigger/condition/duration/save |
| 背包、药水、卷轴与魔法物品 | resource/target/heal/damage/condition |
| 技能检定与社交探索 | target/roll/save/choice |
| 陷阱、地形、机关与环境 | trigger/range/save/damage/move/condition |
| 短休、长休与恢复 | trigger/resource/heal/duration |
| 战利品、任务和战后结算 | reward/choice/resource |
| 推进台 AI 提案 | 只生成计划草稿；DM 确认后调用同一解释器 |

## 自动化等级

- `automatic`：所有会改状态的积木都有可靠结构化字段。
- `assisted`：可自动计算一部分，但需要玩家报骰或 DM 选择分支。
- `manual`：只有来源文字或存在未解析的特殊条件，不自动猜测。

自动化等级由编译和校验结果决定，不能由模型自行宣称。

## 数据来源和例外

本地 2024 官方规则记录是默认来源。编译器保留来源记录 ID、路径、版本和
未解析原因。大多数规则由数据表达；真正无法由通用积木表达的少数能力使用
有名称、有版本且有测试的扩展处理器，不能在页面组件中散落特殊判断。

## 迁移原则

旧的 `damage`、`range`、`save_dc` 等字段暂时保留，规则计划作为并行的
规范字段逐步接管目标预览、资源检查和结算。任何阶段都必须做到：

- 旧角色和旧战斗仍可读取；
- 新规则计划可以降级为旧字段；
- 未解析规则宁可要求 DM 裁定，也不虚构伤害、DC 或持续时间；
- 预览与确认使用同一计划摘要和幂等键。

## 非战斗 Scene 行动

局域网玩家推进台在战斗外也使用服务端权威规则链：

```text
角色 + 已准备能力 + 公开 Scene 原子
  → 版本化非战斗计划
  → 玩家裸 d20 / 系统代掷 NPC 或怪物豁免
  → 确定性加值与 DC 对比
  → DM 确认
  → 资源、物体状态与推进事件写回
```

`PlayerActionRequest.payload_json` 使用 `1.0` 协议，记录行动者、目标、
距离与资格、资源消耗、投骰归属、规则结果、状态提案和叙事建议。浏览器只提交
行动 ID 与目标；后端必须从绑定角色和当前公开 Scene 重新生成规则计划，不能信任
客户端上传的规则字段。

第一批可写积木包括：

- 玩家输入裸 d20，服务端加入属性、熟练与专精；
- 命令术一类效果由系统为 NPC/怪物进行豁免；
- DM 确认时才消耗法术位或角色资源；
- 撬锁、解除陷阱、宝箱和传送机关的状态提案带旧状态检查；
- 确认后生成公开推进事件并同步给 DM 与玩家。

隐形、命令等叙事效果只生成条件和后果建议，不伪装成已经完整实现了虚构世界效果；
隐藏事实和后续叙事仍由 DM 决定。
