# 第 3 批：休息、生命骰与统一资源恢复

## 目标

在 D&D 5e 2024 默认规则下，为单个角色和队伍提供可审计、可预览、由 DM 确认且原子提交的短休/长休流程。

## 规则边界

- 短休至少 60 分钟，开始时角色必须至少有 1 HP。
- 短休可逐枚消耗生命骰；每枚恢复 `骰值 + 体质调整值`，最低 1，且不超过最大 HP。
- 只有显式标记为 `short_rest` 的资源在短休恢复。
- 中断短休不产生收益，但仍可推进已流逝的战役时间。
- 长休至少 8 小时；完成后恢复全部 HP、降低 1 级疲劳，并恢复显式标记为
  `short_rest` 或 `long_rest` 的资源。
- `dawn`、`special` 和未知恢复时机不会被休息自动恢复。
- 2024 规则没有在当前本地权威记录中明确给出长休自动恢复生命骰，因此本批不自动补充生命骰；
  后续规则库提供可引用的明确规则后再启用。
- 若战役世界时间为空，不擅自使用现实时间；预览返回警告并保持为空。
- 长休开始间隔、环境是否安全、中断是否可折算短休由 DM 在预览中确认或覆盖。

## 数据模型

- `resource_pools`：角色资源权威池，兼容同步现有 `Character.resources` JSON。
- `rest_records`：一次休息的请求、结果、世界时间、幂等键与操作事务引用。
- `rest_recovery_entries`：每项 HP、生命骰、资源、疲劳、时间变化的前后值与规则解释。

## API

- `GET /api/v1/campaigns/{campaign_id}/resources`
- `POST /api/v1/campaigns/{campaign_id}/rests/preview`
- `POST /api/v1/campaigns/{campaign_id}/rests/confirm`
- 确认请求必须携带预览令牌、角色版本和幂等键。
- 任一参与角色版本冲突、资源不足或范围不合法时，整个队伍休息回滚。

## UI

- 角色页显示 HP、生命骰、职业资源、法术位及恢复时机。
- 角色页可发起个人短休/长休。
- 游戏推进台可选择队伍成员发起队伍休息，逐人选择生命骰和 DM 排除项。
- 确认前展示所有前后变化、规则来源、警告与世界时间影响。

## 验证

- 纯领域规则单元测试。
- API 原子性、幂等、版本冲突、时间为空、中断与恢复范围测试。
- Alembic 全链升级测试。
- 前端类型检查、组件测试、构建。
- 浏览器检查角色页和推进台休息流程。
