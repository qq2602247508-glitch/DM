# 战斗效果与结算实施计划

**目标：** 完成战斗批次剩余的状态/专注生命周期，以及一次性、原子化的
战斗结算回写，替换前端逐角色写经验的非原子流程。

## 任务 1：效果与专注事务

- 先写 API 测试：效果预览只读；新专注会列出旧专注及其派生效果；
  DM 确认后旧效果结束、新效果建立；重复确认幂等。
- 提供效果列表、创建预览/确认、手动结束接口。
- `combatants.concentration` 只保存当前专注效果引用；完整状态以
  `combat_effects` 为准。

## 任务 2：专注检定

- 从已确认伤害动作读取专注 DC，不接受客户端伪造 DC。
- DM 录入最终体质豁免总值并确认。
- 成功保留专注；失败原子结束专注及派生效果并写战斗日志。

## 任务 3：到期提示

- 回合推进返回到期效果和回合开始/结束触发提示。
- 系统只提示，不静默删除；DM 在效果面板确认结束。

## 任务 4：一次性战斗结算

- 新增持久化 `combat_settlements`。
- 预览选择参与角色、经验分配、HP/持续状态回写项。
- 确认时在单一事务中更新角色、锁定战斗结算并保存前后快照。
- 重复提交幂等；已经结算的战斗拒绝不同请求。

## 任务 5：前端

- 战斗员卡增加结构化效果与专注面板。
- 伤害后直接显示专注检定输入。
- 战斗结束页改为结算预览与一次 DM 确认，不再循环调用角色更新接口。

## 任务 6：质量门禁

- 全量后端测试、严格 Mypy、Ruff。
- 前端 Vitest、TypeScript、ESLint、生产构建。
- 现有数据库副本迁移。
- 右侧网页走通效果建立、专注切换和结算预览。
