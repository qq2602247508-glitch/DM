# 职业/子职业特性自动化执行准备报告

日期：2026-08-07  
范围：2024 核心 12 职业 1–20 级 + 56 个子职业显式等级特性

## 结论

当前问题不是“完全没有积木”，而是“积木执行器与499条特性的生产配置迁移没有批量化”。

当前固定分母 499：

| 状态 | 数量 | 占比 |
|---|---:|---:|
| full | 161 | 32.3% |
| partial | 246 | 49.3% |
| dm_only | 92 | 18.4% |

本报告严格区分：

- 积木需求类别：规则可以归入哪种通用语义；
- 通用执行器：不识别职业/特性 ID 的可复用代码；
- 生产接线：至少一个真实特性配置接入真实消费者；
- `full`：该条特性完整改变真实状态，输入、资源、生命周期和幂等链都闭环。

## 当前执行器状态

### 已有真实生产闭环的 13 个主领域

- 成长授予、属性提升、专精和部分熟练授予；
- 施法能力与固定始终准备法术表；
- 动作/触发/资源/目标政策的统一职业动作链；
- 资源生命周期与休息恢复；
- 基础伤害/治疗/临时生命；
- 伤害前防御干预；
- 光环/范围被动；
- 被动数值修正、防御、熟练加值；
- 豁免/DC 的部分自动结算；
- 基础移动/位移；
- 通用 `zero_hp_intervention`；
- 状态生命周期；
- 召唤/伙伴生命周期。

### 已有执行器但生产迁移仍不完整的 2 个领域

- `roll_intervention`：已有通用重骰、加骰、优势、最低值、替换和失败补救语义；部分生产路径已经接线，但仍有特性使用旧兼容路径。
- `attack_rider`：已有命中后窗口、目标豁免、资源和状态效果链；复杂附伤、多分支、并发 CAS 和部分旧特性迁移仍未完全收口。

### 不属于可强行全自动的 1 个边界

DM/开放叙事、未结构化选择、实际骰子、缺少权威位置或环境事实的规则，必须保留玩家/DM 输入，不能为了提高 `full` 数量而猜测。

## 为什么最近一批只有 +2

最近治疗骰池批次只找到两个满足完整闭环的生产特性：神之勇者、治愈之光/治疗之光。它们共享同一个治疗骰池执行器，但不是把“资源候选195条”全部迁移。

其余候选至少缺一项：

- 规则分支仍需要选择；
- 目标、位置、阵营或环境事实不完整；
- 只有字段，没有真实消费者；
- 只有纯函数执行器，没有持久化确认链；
- 仍需后续攻击、状态、移动或持续效果；
- 玩家骰值/DM裁定边界尚未完成。

## 批量自动化必须增加的层

下一步不应继续手写单个特性，而应实现“特性迁移预审器/迁移工厂”：

1. 对499条特性生成规范化字段图：触发、资格、动作、资源、目标、范围、骰子/DC、效果、持续时间、恢复。
2. 按执行器模板聚类，自动列出每个模板的 `eligible_now`、`missing_fields`、`missing_consumer`、`manual_boundary`。
3. 只对同一模板中 `eligible_now` 的全部条目批量生成配置和回归样例。
4. 批量接入真实消费者后重新审计，并输出精确 `full` 增量。
5. 预审阶段如果没有至少一批明确可闭环的条目，就不提前承诺新增数量。

本报告不把 22 个候选标签、195 条资源命中或测试 fixture 计为已完成自动化。
