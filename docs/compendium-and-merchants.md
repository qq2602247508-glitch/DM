# 原子图鉴、角色实例与商店

系统把内容分为三层，避免官方资料、原创模板和实际游戏状态互相污染。

1. **官方原子层**：直接读取 `data/generated-content/dnd5e_chm/json` 中已标记为
   `official` 的规则资料。它是只读目录，不会为了“填满图鉴”而向每个团重复写入
   数千条记录。
2. **团内原创原子层**：AI 或 DM 创建的新怪物、装备和道具写入
   `compendium_entries`，带有原创来源标签并按团隔离。
3. **运行实例层**：给予角色、加入 Scene、生成商店或拾取战利品时，才创建
   `WorldItem`、`MonsterInstance`、角色法术/特性或 `ShopInventory` 等可改变状态的
   实例。

因此，“角色背包与装备”只管理角色实际拥有的物品、负重、装备、同调、充能和交易；
规则资料查阅与授予使用“原子图鉴”；地点中的买卖准备使用“商人与商店”。

商店生成先做预览，再由 DM 确认。选货按地点/Scene、商品类别、等级、角色等级与职业
进行约束。能匹配官方原子时直接引用官方来源；确实需要原创补位时，确认后先写入团内
原创图鉴，再创建该商店的库存实例。商品价格使用铜币作为权威单位。

站点生成器同样遵循这一边界：生成计划中的官方怪物会优先绑定同名官方图鉴数值；
没有匹配时才使用受控后备数值。确认生成后，怪物/NPC 会成为 Scene Token，战利品会
成为隐藏 Scene Object，并与 Scene、战斗共用同一套一基坐标网格。玩家端仍由服务端
战争迷雾与可见性过滤，不会因为 DM 图鉴或生成计划而看到未探索内容。
